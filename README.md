# 우리 동네 시장님

## 기본 플레이: 살아가는 새봄동

시나리오를 선택하지 않고 하나의 도시를 계속 운영합니다. 주민이 현재 문제를 이야기하고, 지도에서 정책을 시행하면 차량·쓰레기·하천 상태를 유지한 채 변화가 이어집니다. 불법주차, 수거, 무단투기, 수질, 물류, 시설 접근성을 같은 도시에서 살펴봅니다.

- **시작과 지도 보기**: 왼쪽 세로 목록에서 지도를 고릅니다. 새 도시는 기본 4배속에서 약 30초간 둘러본 뒤 지속되는 문제를 차례로 알립니다. 말풍선은 한 번에 하나만 표시하며 지난 이야기는 동네 소식에서 다시 확인합니다.
- **동네 소식**: 문제 발생·호전·정책 반응과 연결된 변화를 확인합니다.
- **동네 소식 → 주민 회의**: 지도에서 장소를 정하고 서로 다른 주민의 이야기를 하나씩 듣습니다. 함께 걷기·배출 약속·생활하수 줄이기의 실천 방법을 선택하고, 활동 뒤 남은 문제와 다음 행동을 기록합니다.
- **주민 만족도**: 상단 게이지가 지금 만족도와 1분 전 대비 변화(▲▼)를 보여 줍니다. 누르면 분야별 점수와 근거 수치, 정책 시행 시점이 표시된 시간 그래프를 볼 수 있습니다. 실제로 잰 불편 수치에서 계산하며 예산이나 도시 상태에는 영향을 주지 않습니다. 정책 반응과 문제 호전 때는 지도 위 그 장소에 만족도 변화가 떠오르고, 준비 시간이 있는 정책에는 효과가 시작될 때까지 남은 시간이 표시됩니다.
- **정책 만들기**: 분야를 고르고 지도에서 위치를 지정합니다. 예산 100으로 시작하고 도시 시간 5분마다 운영 예산 20을 받습니다.
- 주민 말풍선을 직접 열면 읽는 동안 유지됩니다. **이 문제 살펴보기**에서 관련 지도·정책으로 이어지고, 지난 소식의 근거도 다시 볼 수 있습니다.
- **도시 살펴보기 / 조사 기록**: 현재 수치를 시점과 함께 기록하고, 원인과 다음 행동을 적습니다.
- 자동 저장과 JSON 저장/불러오기로 이어 할 수 있습니다. 앱을 닫은 동안에는 시간이 흐르지 않습니다.
- 현재 도시 상태도 함께 저장해 새로고침 때 빠르게 이어 갑니다. 이전 기록이나 다른 기기의 JSON은 처음 한 번 계산하며, 불러오기를 중단해도 원본은 유지합니다. 화면이 느리면 **도움말 → 화면 품질 → 가볍게**를 선택합니다.
- **조사 기록 / 도움말 → 저장 초기화**에서 도시 기록과 이어하기 상태를 지우고 새로 시작할 수 있습니다. 불러오는 중에도 사용할 수 있고, 확인창에서 취소하거나 기존 기록을 파일로 보관할 수 있습니다.

[통합 모델과 범위](docs/LIVING_CITY.md). 아래의 개별 실험 설명은 `/?mode=lab`에 남겨 둔 기존 비교 실험에 해당합니다.


**강 아래쪽 물은 왜 더러울까요?**에서는 상류·배출구 아래·하류를 같은 조사 수첩으로 탐구합니다. 지도에서 유입구 처리·생활하수 시설·하천변 청소를 선택하고, 물에 섞인 오염과 쓰레기, 하류까지 걸리는 시간, 지도 밖 유출을 세 차례 관찰합니다. [수질 모형과 범위](docs/WATER.md)

**치웠는데 또 쌓이는 쓰레기**에서는 골목·공터 옆·하천변의 무단투기를 조사합니다. 청소·지정 배출 장소·안내 활동을 지도에서 선택하고, 5분씩 세 번 관찰해 재발·넘침·다른 수거장의 지연을 비교합니다. 공통 조사 수첩과 기록 저장·인쇄를 지원합니다. [무단투기 모형과 범위](docs/DUMPING.md)

**우리 동네 조사**에서 현장 찾기 → 원인 조사 → 의견 듣기 → 해결책 결정 → 시행·비교 → 수정 제안을 한 단계씩 진행합니다. 자료와 주민 의견을 담고 선택 근거를 기록해 저장·인쇄할 수 있습니다. **길을 막은 불법주차** 사례는 학교 앞·시장 옆·주거지의 실제 차량 대기와 보행 우회를 관찰하고, 순찰·공동주차장·잠깐 정차 공간을 위치와 예산에 맞춰 비교합니다. [조사 수첩·불법주차 모형과 범위](docs/PARKING.md)

현재 지도는 기존 대비 **면적 4배**입니다. 주거·상업·산업지구, 하천과 다리, 외부 물류도로, 자원순환센터와 6개 건설 공터를 포함합니다. **지구·공터**에서 위치를 살펴보고 시설 계획에서 공터 크기와 예산을 함께 비교합니다. [지도 확장 상세](docs/EXPANSION.md)

외부 도로는 지도 가장자리까지 이어지고 차량은 경계에서 들어오고 나갑니다. 출퇴근 차량은 서쪽 주거지와 강 건너 상업·산업지구 사이를 실제 다리로 이동합니다. 강 건너에는 출근 시간대 정체, 상가 거리 불법주차, 상점가 수거장, 작업장 배출구 아래 오염이 생기고 강너머 상가 가게에도 물건이 배송되며 **출근 시간 나누기**·강 건너 신호 조절·공터 E 상가 주차장 등으로 해결해 봅니다. [강너머 지구 설계](docs/EAST_BANK_PLAN.md)

초등학교 4학년 사회과를 위한 **3D 도시 문제 해결 시뮬레이터**. **막히는 등굣길**, **쓰레기가 쌓이는 동네**, **우리 동네에 필요한 시설은?**, **개발할까요, 보전할까요?**, **시장에 물건이 부족해요**를 선택해 주민 의견과 자료를 바탕으로 정책을 비교합니다. 실제 차량·보행자·수거차를 관찰하고, 시설 계획에서는 예상 접근성·정원을, 개발 계획에서는 이용 공간·녹지·추가 교통·가상 환경 부담을 함께 살펴봅니다.

동네 소식 → **다른 도시 문제 살펴보기**에서 시나리오를 바꿉니다. **시장에 물건이 부족해요**에서는 공장·이웃 마을의 물자가 실제 화물차로 상점에 도착하는 과정을 관찰합니다. [Phase 0·1 수거와 공통 구조](docs/EXPANSION.md), [Phase 2 공공시설과 주민 참여](docs/FACILITIES.md), [Phase 3 개발과 환경](docs/ENVIRONMENT.md), [Phase 4 물류와 지역 간 교류](docs/LOGISTICS.md)를 참고하세요.

## 설치와 실행

Node.js **22.15 이상인 22.x 또는 24 이상**과 npm이 필요합니다. DOM 회귀 검사를 포함한 개발 검증에는 Node 24.14.1을 사용했습니다.

```powershell
npm ci
npm run dev
```

터미널에 표시된 Local 주소를 브라우저에서 여세요. 기본 포트는 5173이며 이미 사용 중이면 다음 포트를 사용합니다. 다른 앱이 쓰는 포트를 종료할 필요가 없습니다.

```powershell
npm run build
npm run preview
```

빌드 결과는 `dist/`입니다. 이 폴더를 정적 호스팅에 올리면 됩니다. GitHub Pages 전용 경로를 제거하고 상대 경로로 빌드합니다. `file://`로 index.html을 직접 여는 대신 정적 HTTP 서버를 사용하세요. 게임용 백엔드·로그인·유료 API·외부 폰트가 필요하지 않습니다. 의존성 설치 후에는 외부 네트워크 요청 없이 로컬에서 플레이할 수 있습니다.

## 플레이 방법

물류 시나리오는 **상품 재고 지도·물류 현황 → 주민 의견 → 정책 만들기 → 결과 비교**로 진행합니다. 상점 네 곳의 재고를 녹색·노랑·주황·빨강으로 보고, 화물차를 누르면 실은 물자·출처·목적지·경로를 확인합니다. 지름길·추가 차량·하역 지원·외부 공급처를 예산 안에서 선택해 5·10·15분을 비교합니다. 차가 실제 도착해 내리기 전에는 상점 재고가 늘지 않습니다. 공급처·상점 목록과 상세 결과는 펼칠 때만 표시합니다.

왼쪽 지도 버튼에서 현재 도시 문제에 맞는 **혼잡도·쓰레기·시설 접근성·환경 부담·인구·시설**을 골라 봅니다. 한 번에 하나만 표시하며 같은 버튼을 다시 누르면 일반 도시로 돌아갑니다. 쓰레기는 수거하는 6곳의 건물이 **흰색(0봉투) → 진한 갈색(60봉투 이상)**으로 바뀝니다. 시설 접근성은 도서관/공원을 고르면 주택 7곳을 **녹색(2분 이내)·노랑(2~4분)·주황(4~5분)·빨강(5분 초과)**으로 표시하고, 보도·횡단보도에 예상 도보 5분 범위를 그립니다. 이용 가능 인원과 필요한 주민 수도 함께 표시합니다.

하단 **주민 의견**을 누르면 해당 동네에 말풍선 표식이 나타납니다. 표식을 눌러 한 주민의 짧은 이야기를 읽고, 필요하면 **관찰한 사실과 자세한 의견**을 펼쳐 보세요. 선택한 지역은 노란 테두리와 연결선으로 알려 줍니다. 이전·다음 버튼으로 모든 주민의 의견을 차례로 들을 수 있습니다.

시행한 정책은 지도 위 해당 장소에 **시행 중**으로 표시합니다. 수거 운영처럼 넓게 적용하는 정책은 상단 **동네 전체**, 개발 규모 축소는 **개발 부지 공통**으로 구분합니다. 표식을 누르면 적용 내용과 유의할 점을 읽을 수 있습니다. 아직 시행하지 않은 선택은 지도 표시를 바꾸지 않습니다.

개발·환경 시나리오는 **환경 자료 → 개발 부지·지역별 부담·주민 의견 → 정책 만들기**로 진행합니다. 산업·주거 확장, 녹지 보전·완충 식재·규모 축소를 고릅니다. 기존 차량 140대·보행자 60명은 그대로 두고 개발 규모에 따라 실제 차량을 추가해 3·7·10분을 비교합니다. 환경 점수는 시설 거리와 실제 도로 위 차량으로 계산한 **교육용 가상 지표**이며 실제 오염·소음·건강 위험 수치가 아닙니다.

시설 시나리오에서는 **시설 지도 → 동네별 접근성·주민 의견 → 정책 만들기** 순으로 살펴봅니다. 북쪽·서쪽·남쪽 마당 중 부지를 고르고 도서관 신설·공원 조성·기존 도서관 확장·출입로 개방을 비교합니다. 시행 즉시 계획 1회 결과가 열리며 지역별 수혜와 정원 부족을 확인합니다. 화면의 이용 가능 인원은 가상 주민 680명에 대한 계산 결과입니다. 교통·수거처럼 경과 시간을 재거나 실제 도착 인원으로 표현하지 않습니다.

기본 교통 시나리오의 흐름은 다음과 같습니다.

1. 08:00부터 출발하는 자동차 140대와 보행자 60명을 관찰합니다. 학교·주거지·공원 앞 네 횡단보도에서 신호를 기다리고 건넙니다. 하단 **동네 소식 → 학교 앞 교차로 살펴보기**를 누르면 병목을 가까이 봅니다. 지도 위 장소를 직접 클릭해도 정보를 볼 수 있습니다.
2. **혼잡도**로 도로 상태를 확인합니다. 하단 **교통 현황**에서 통계를, 그 안의 **시간별 변화와 막히는 길**을 펼쳐 그래프와 도로별 수치를 봅니다. 시간 조작 바의 **끝까지**는 같은 엔진을 관찰 종료 시점까지 빠르게 계산합니다. 기본 관찰 시간은 7분입니다.
3. 하단 **정책 만들기**에서 예산 100 안으로 정책을 선택합니다. 신호 15, 우회도로 55, 일방통행 30이며 함께 선택할 수 있습니다.
4. **선택한 정책 시행하기**를 누릅니다. 같은 시드·출발지·목적지·출발 예정 시각으로 08:00부터 다시 움직입니다.
5. 관찰 시간이 끝나면 결과를 비교합니다. **누가 더 편해졌을까요?**를 펼치면 등교·출근·귀가 또는 이동 방향별 영향을 봅니다. **같은 자동차끼리 비교하기**에서는 전후 모두 도착한 같은 차량들의 이동·대기시간을 비교합니다. **걸어가는 사람들은 어땠을까요?**에서는 같은 보행자들의 도착 수와 누적 대기를 비교합니다. 상세 분석은 한 번에 하나만 열립니다.
6. 생각을 적고 **실험 기록 저장**으로 조건·수요·전후 통계·상세 분석을 담은 JSON을 내려받습니다. 다른 정책으로 다시 실험할 때 예산은 다시 100에서 계산합니다.
7. **동네 소식** 안의 실험 조건을 펼치면 세 가지 아침과 3·7·10분 관찰 시간을 고를 수 있습니다. **이 조건으로 새로 관찰**을 누르면 이전 비교와 생각을 지우고 새 관찰을 시작합니다. 각 정책 비교 안에서는 출발 조건과 관찰 시간이 항상 같습니다.

| 하단 도구 버튼          | 해당 정보창 하나만 열기·접기         |
| Esc / 정보창의 ×        | 정보창 닫기, 실행한 도구로 초점 복원 |
| 1·2·4·8배속             | 시뮬레이션 시간 진행 속도            |
| 처음부터                | 기본 도시와 예산 복원                |
| 도움말 → 화면이 느릴 때 | 보통/가볍게 선택, 선택한 품질 기억   |
| 스피커 버튼             | 정책 효과음 켜기·끄기, 기본 음소거   |

화면은 [Cities: Skylines의 UI 참고 화면](https://interfaceingame.com/games/cities-skylines/)에서 도시 중심 배치, 하단 도구 바, 선택할 때 열리는 도구 창의 구조를 참고했습니다. 기본 상태에서는 정보창을 모두 접고, 하나를 열면 다른 창을 닫습니다. 정책 시행 시에는 창을 닫아 도시의 변화를 볼 수 있습니다. 기존 3D 도시·아이콘과 한국어 학습 콘텐츠를 그대로 활용했습니다. 화면 구성은 `src/ui/layout.ts`, 정보창 동작은 `src/ui/panels.ts`에 분리했습니다.

첫 번째 아침의 7분 관찰에서 기본 도착 **28대 → 신호 조절 65대**, 전체 1대당 누적 대기 **242.4초 → 189.0초**로 계산되었습니다. 일방통행 단독은 도착 18대로 역효과를 보였고, 세 정책 조합은 51대로 신호 조절만 했을 때보다 적었습니다. 정책을 많이 쓰는 것이 항상 유리하지는 않습니다. 이 숫자는 코드에 입력한 효과 상수가 아니라 실제 주행 결과입니다. [자세한 검증 결과](docs/VERIFICATION.md)를 참고하세요.

같은 진입·진출 경로에서는 교차로 안에서도 앞차를 따라갑니다. 정차 행렬의 직진 배출 간격은 평균 2.23초로 공개 문헌의 일반적인 포화교통량 범위와 비교했습니다. 특정 도로의 현장 보정은 아직 하지 않았습니다. 서로 다른 상충 경로는 전체 구간을 예약하는 보수적 모델입니다. 차로 변경은 현재 시나리오의 같은 방향 2차로 구간에서 지원합니다. 보행자는 네 곳의 단방향 보도·횡단보도 경로를 지원합니다. 시설 계획의 보행 경로 계산은 도시 전체 보도망을 사용하지만, 도시 전체 주민의 보행 애니메이션과 자유 도로 편집은 미구현입니다. 다음 개발은 지역 홍보 시나리오이며 학교 PC 실측과 수업 적용도 남아 있습니다. 효과음은 형식·파형을 확인했으며 청취 평가는 하지 않았습니다. 초기 안내·게임 코드·Three.js를 분리했으며 빌드 크기 경고는 없습니다. 도움말에서 ‘가볍게’를 선택하면 그림자를 끄고 최대 30FPS로 그립니다. 교통 계산과 실험 결과는 동일합니다.
