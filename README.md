# 우리 동네 시장님

초등학교 4학년 사회과를 위한 **실제로 움직이는 3D 도시 문제 해결 시뮬레이터**. 첫 시나리오는 **막히는 등굣길**입니다. 시장이 되어 대기 행렬을 관찰하고 신호 조절·우회도로·일방통행 정책을 시행한 뒤, 같은 출발 조건으로 결과를 비교합니다.

## 설치와 실행

Node.js **22.12 이상**과 npm이 필요합니다. 개발 검증에는 Node 24.14.1을 사용했습니다.

```powershell
npm ci
npm run dev
```

터미널에 표시된 Local 주소를 브라우저에서 여세요. 기본 포트는 5173이며 이미 사용 중이면 다음 포트를 사용합니다. 다른 앱이 쓰는 포트를 종료할 필요가 없습니다.

```powershell
npm run build
npm run preview
```

빌드 결과는 `dist/`입니다. 이 폴더를 정적 호스팅에 올리면 됩니다. GitHub Pages 전용 경로를 제거하고 상대 경로로 빌드합니다. `file://`로 index.html을 직접 여는 대신 정적 HTTP 서버를 사용하세요. 게임용 백엔드·로그인·유료 API·외부 폰트가 필요하지 않습니다. 의존성 설치 후에는 외부 네트워크 요청 없이 로컬에서 플레이할 수 있습니다.

## 플레이 방법

1. 08:00부터 출발하는 자동차 140대와 보행자 60명을 관찰합니다. 학교·주거지·공원 앞 네 횡단보도에서 신호를 기다리고 건넙니다. 하단 **동네 소식 → 학교 앞 교차로 살펴보기**를 누르면 병목을 가까이 봅니다. 지도 위 장소를 직접 클릭해도 정보를 볼 수 있습니다.
2. **혼잡도**로 도로 상태를 확인합니다. 하단 **교통 현황**에서 통계를, 그 안의 **시간별 변화와 막히는 길**을 펼쳐 그래프와 도로별 수치를 봅니다. 시간 조작 바의 **끝까지**는 같은 엔진을 관찰 종료 시점까지 빠르게 계산합니다. 기본 관찰 시간은 7분입니다.
3. 하단 **정책 만들기**에서 예산 100 안으로 정책을 선택합니다. 신호 15, 우회도로 55, 일방통행 30이며 함께 선택할 수 있습니다.
4. **선택한 정책 시행하기**를 누릅니다. 같은 시드·출발지·목적지·출발 예정 시각으로 08:00부터 다시 움직입니다.
5. 관찰 시간이 끝나면 결과를 비교합니다. **누가 더 편해졌을까요?**를 펼치면 등교·출근·귀가 또는 이동 방향별 영향을 봅니다. **같은 자동차끼리 비교하기**에서는 전후 모두 도착한 같은 차량들의 이동·대기시간을 비교합니다. **걸어가는 사람들은 어땠을까요?**에서는 같은 보행자들의 도착 수와 누적 대기를 비교합니다. 상세 분석은 한 번에 하나만 열립니다.
6. 생각을 적고 **실험 기록 저장**으로 조건·수요·전후 통계·상세 분석을 담은 JSON을 내려받습니다. 다른 정책으로 다시 실험할 때 예산은 다시 100에서 계산합니다.
7. **동네 소식** 안의 실험 조건을 펼치면 세 가지 아침과 3·7·10분 관찰 시간을 고를 수 있습니다. **이 조건으로 새로 관찰**을 누르면 이전 비교와 생각을 지우고 새 관찰을 시작합니다. 각 정책 비교 안에서는 출발 조건과 관찰 시간이 항상 같습니다.

| 조작                    | 동작                                 |
| ----------------------- | ------------------------------------ |
| 왼쪽 드래그             | 카메라 회전                          |
| 오른쪽 드래그           | 카메라 이동                          |
| 마우스 휠 / +·− 버튼    | 확대·축소                            |
| 집 모양 버튼            | 전체 도시 시점                       |
| 건물·도로·교차로 클릭   | 정보와 선택 강조                     |
| 스페이스 / 재생 버튼    | 일시정지·재생                        |
| 하단 도구 버튼          | 해당 정보창 하나만 열기·접기         |
| Esc / 정보창의 ×        | 정보창 닫기, 실행한 도구로 초점 복원 |
| 1·2·4·8배속             | 시뮬레이션 시간 진행 속도            |
| 처음부터                | 기본 도시와 예산 복원                |
| 도움말 → 화면이 느릴 때 | 보통/가볍게 선택, 선택한 품질 기억   |
| 스피커 버튼             | 정책 효과음 켜기·끄기, 기본 음소거   |

화면은 [Cities: Skylines의 UI 참고 화면](https://interfaceingame.com/games/cities-skylines/)에서 도시 중심 배치, 하단 도구 바, 선택할 때 열리는 도구 창의 구조를 참고했습니다. 기본 상태에서는 정보창을 모두 접고, 하나를 열면 다른 창을 닫습니다. 정책 시행 시에는 창을 닫아 도시의 변화를 볼 수 있습니다. 기존 3D 도시·아이콘과 한국어 학습 콘텐츠를 그대로 활용했습니다. 화면 구성은 `src/ui/layout.ts`, 정보창 동작은 `src/ui/panels.ts`에 분리했습니다.

## 구현과 검증

- 보행 신호·대기 줄·횡단 중 차량 양보, 보행자 60명의 불변 수요와 별도 대기 비교
- 16블록의 실제 Three.js 3D 도시, 인스턴싱 차량, 신호·회전·대기 행렬
- 0.1초 고정 계산, 시드 수요, 방향별 차로, Dijkstra, IDM 추종
- 차량의 회전 경로와 차체 범위로 충돌 여부 판정, 안전한 방향의 동시 통과, 출구 예약
- 동일 이동의 교차로 내 연속 추종, 정차 공간을 고려한 출구 예약과 막힘 회복
- 초록불 직진 속도 유지, 호 길이 기반 회전, 실제 신호·도로망에 적용되는 세 정책
- 회전 방향에 맞는 차로 선택, MOBIL 안전·이득 판단과 연속적인 차로 변경
- 같은 수요·관찰 시간 비교, 목적별·방향별 영향과 동일 차량 비교
- 한글 UI, 도로 혼잡도, 변화 그래프, 반응형 화면, 실험 기록
- 저사양 기기를 위한 가벼운 화면, 그림자·해상도·화면 갱신 조절, 분리된 초기 로딩

```powershell
npm test
npm run test:browser
npm run verify:report
npm run verify:experiments
npm run verify:capacity
npm run verify:performance
npm run build
npm run verify:production
```

엔진·분석·기하 테스트 36개와 실제 Chrome 브라우저 테스트 5개를 통과했습니다. `npm run test:browser`는 설치된 Google Chrome을 사용합니다. 다른 환경에서는 `playwright.config.ts`의 `channel`을 조정하거나 Playwright Chromium을 준비하세요. 빌드 성공과 전체 플레이 콘솔 오류 0건을 확인했습니다.

첫 번째 아침의 7분 관찰에서 기본 도착 **28대 → 신호 조절 65대**, 전체 1대당 누적 대기 **242.4초 → 189.0초**로 계산되었습니다. 일방통행 단독은 도착 18대로 역효과를 보였고, 세 정책 조합은 51대로 신호 조절만 했을 때보다 적었습니다. 정책을 많이 쓰는 것이 항상 유리하지는 않습니다. 이 숫자는 코드에 입력한 효과 상수가 아니라 실제 주행 결과입니다. [자세한 검증 결과](docs/VERIFICATION.md)를 참고하세요.

## 오픈소스

기본 프로젝트는 [Sudoyan118/mini-traffic-city-sim](https://github.com/Sudoyan118/mini-traffic-city-sim)이며, 원본 TypeScript·Three.js·Vite 구성 및 도로·로우폴리 렌더링 방식을 재사용·수정했습니다. 무작위 BFS와 비동기 차량 재생성은 교체했습니다. 원본 코드와 MIT 고지는 `vendor/mini-traffic-city-sim/`, 루트 `LICENSE`에 보존했습니다.

[SaintPepsi/traffic-microsim](https://github.com/SaintPepsi/traffic-microsim)의 `desiredGap`·`idmAccel`과 MOBIL 안전·이득 계산을 TypeScript로 이식했습니다. MIT, **Copyright (c) 2026 Ian Hogers**. 분석한 소스와 라이선스는 `vendor/traffic-microsim/`에 보존했습니다. 차로 변경에는 도시 경로, 교차로 예약, 이동 중 두 차로 점유와 연속적인 차체 이동을 추가했습니다.

같은 진입·진출 경로에서는 교차로 안에서도 앞차를 따라갑니다. 정차 행렬의 직진 배출 간격은 평균 2.23초로 공개 문헌의 일반적인 포화교통량 범위와 비교했습니다. 특정 도로의 현장 보정은 아직 하지 않았습니다. 서로 다른 상충 경로는 전체 구간을 예약하는 보수적 모델입니다. 차로 변경은 현재 시나리오의 같은 방향 2차로 구간에서 지원합니다. 보행자는 네 곳의 단방향 보도·횡단보도 경로를 지원합니다. 도시 전체의 보행 경로 탐색과 자유 도로 편집은 미구현이며 다음 우선순위는 학교 PC 실측과 수업 적용입니다. 효과음은 형식·파형을 확인했으며 청취 평가는 하지 않았습니다. 초기 안내·게임 코드·Three.js를 분리했으며 빌드 크기 경고는 없습니다. 도움말에서 ‘가볍게’를 선택하면 그림자를 끄고 최대 30FPS로 그립니다. 교통 계산과 실험 결과는 동일합니다.
