# 화면 품질과 성능 측정

도움말 `?` → **화면이 느릴 때**를 펼쳐 화면 품질을 선택한다. 새 정보창이나 항상 보이는 성능 계기판은 추가하지 않았다.

| 설정                | 보통      | 가볍게 |
| ------------------- | --------- | ------ |
| 3D 해상도 배율 상한 | 1.5       | 1      |
| 그림자              | 2048px 맵 | 끔     |
| 그리기 빈도 상한    | 60FPS     | 30FPS  |
| HTML 글자·버튼      | 동일      | 동일   |
| 교통 계산·수요·정책 | 동일      | 동일   |

고해상도 화면에서는 3D 캔버스의 프레임당 픽셀 수가 보통의 약 44%가 된다. 화면 주사율과 실제 부하에 따라 표시 빈도는 달라진다. 품질 전환 시 실험을 초기화하지 않고, 같은 시드와 관찰 종료 시각에서 결과도 같다. localStorage에 선택을 기억하며 저장 접근을 막은 브라우저에서도 현재 선택은 적용한다. WebGL 안티앨리어싱은 두 모드 모두 유지한다.

`RenderClock`은 다음 그리기 시각을 누적한다. 144Hz처럼 60으로 나누어떨어지지 않는 화면에서도 시간을 버리지 않아 60/30FPS의 평균 빈도를 유지한다. 긴 중단 뒤에는 누락한 그리기를 한꺼번에 실행하지 않는다. 교통 엔진의 0.1초 고정 계산은 프레임 제한과 분리되어 있다.

## 초기 로딩

HTML에 도시 준비 안내를 넣고, CSS와 작은 초기 JS가 먼저 열린다. 게임 모듈과 Three.js 청크를 이어서 불러오며 실패하면 다시 열기 버튼을 제공한다. 라이브러리 청크를 별도 캐시할 수 있다. [Vite의 분할 설정](https://vite.dev/guide/build.html#chunking-strategy)을 사용한다.

| 배포 파일 |     원본 |     gzip |
| --------- | -------: | -------: |
| 초기 JS   |   2.78KB |   1.43KB |
| 게임 코드 |  79.34KB |  27.71KB |
| Three.js  | 493.09KB | 123.85KB |
| CSS       |  24.45KB |   6.10KB |

전체 JS는 약 575KB이며 게임 실행에는 세 청크가 모두 필요하다. 500KB를 넘는 단일 청크 경고는 사라졌다. 압축 전송 여부는 정적 서버 설정에 따른다. 다운로드 속도 자체의 개선이나 첫 실행 시간 단축을 실측한 수치는 아니다.

## 재현 방법

```powershell
npm ci
npm run verify:performance
```

설치된 Google Chrome을 사용하며 5174의 개발 서버를 재사용하거나 시작한다. 같은 `CityRenderer`와 `TrafficSimulation`을 불러오는 별도 측정 페이지에서 12조건을 한 번에 하나씩 실행한다. 결과는 `output/performance.json`에 쓴다. 측정 페이지와 검사 객체는 배포 파일에 들어가지 않는다.

- 수요 80·150·300건 × 보통/가볍게 × CPU 감속 없음/4배. 실제 도로 위 차량 수는 별도 기록한다.
- 보행자 60명 고정 수요를 포함하며 실제 활성 보행자 수와 통계도 별도 기록한다.
- 시드 2404, 세 정책 조합, 180초까지 계산한 동일 초기 상태, 2배속 진행.
- 고정 카메라, 화면 1280×720 CSS 픽셀, 기기 배율 1.5. 렌더 준비 1.5초 뒤 5초 측정.
- FPS는 초당 그리기 호출 수, p95는 호출 간격의 95백분위다. 실제 디스플레이의 표시 완료나 GPU 타이머 수치는 아니다.
- 렌더 CPU는 그리기 호출의 동기 실행 시간, 엔진 CPU는 진행·주기적 통계 계산 시간이다. 비동기 GPU 실행 시간은 포함하지 않는다.
- CPU 4배 감속은 Chrome 모의 조건이다. GPU는 같은 실제 장치를 사용한다. 생산 빌드의 전체 HUD, 카메라 이동, 차가운 시작, 8배속은 이 측정에 포함하지 않는다.
- 실행 PC·GPU·브라우저·동시 작업에 따라 달라지는 짧은 관측이다. 보편적인 FPS 통과선을 테스트에 강제하지 않는다.

실제 학교 PC에서는 다른 작업을 줄인 상태로 이 명령을 실행해 파일을 보관한다. 이어서 전체 앱에서 보통/가볍게, 혼잡도, 카메라 조작, 8배속 및 정책 비교를 직접 확인한다. 실제 학교 iGPU 장치에서의 측정과 학생의 글자 크기·움직임 평가는 아직 남아 있다.

배포 파일 검증은 별도로 실행한다.

```powershell
npm run build
npm run verify:production
```

포트 5176에서 dist를 잠시 제공해 초기 안내, 로딩 실패 후 재시도, 가벼운 화면의 기본/신호 실험, JSON 저장과 개발용 검사 객체 제외를 확인한다. 종료 시 서버와 브라우저를 닫는다.
