# Phase 4 — 물류와 지역 간 교류

현재는 `goods-delivery-v2`다. 공장을 산업지구로 옮겼으며 외부 공급처는 도시 경계 밖에 있고 실제 출입 도로와 하역 복귀 경로를 사용한다. 아래 v1 수치·성능은 이전 지도 기록이다. [지도 확장](EXPANSION.md)을 참고한다.

시나리오 04 **시장에 물건이 부족해요**. 동네 소식 → 다른 도시 문제 살펴보기에서 선택한다. 공장·이웃 마을 → 화물차 → 상점 → 소비의 연결과 상점별 차이를 관찰한다. 기본 10분, 선택 5·10·15분, 예산 100이다.

## 생산·소비·운송 규칙

- 북쪽 골목 가게(b2), 동쪽 다함께 시장(b7), 공원 옆 가게(b11), 남쪽 생활 가게(b14)의 4상점. 처음 8~12상자, 분당 4~6상자 수요, 최대 재고 60상자다. 독립된 시드로 정해 비교 전후에 같은 조건을 유지한다.
- 새봄 공장은 처음 30~34상자, 분당 9상자를 생산한다. 동쪽 들녘마을 입구에는 처음 24~28상자, 분당 6상자가 공급된다. 정책으로 여는 서쪽 강빛마을 입구도 같은 범위다. 잠재 공급처까지 먼저 추첨하므로 서쪽을 열어도 기존 공장·동쪽 조건은 변하지 않는다.
- 화물차는 기본 2대, 정책으로 3대다. 한 대당 최대 36상자, 기존 서비스 차량 운행의 목표속도 6.5m/s와 3.8×1.8m 차체를 사용한다. 일반 차량 140대·보행자 60명은 원래 수요를 유지한다.
- 첫 차량은 공장, 두 번째는 외부 입구를 맡는다. 세 번째를 추가하면 공장을 공유한다. 남쪽→공원→동쪽→북쪽의 상점 목록을 차량 수에 따라 나누어 맡고, 한 상점에 내린 뒤 공급처에 돌아가 다음 상점 물자를 싣는다.
- 도로에 실제 진입해 신호·행렬·교차로 예약을 따르고, 지정 차로의 끝 7m 전에서 완전히 정차해야 싣거나 내린다. 선적은 초당 1.2상자이며, 가득 차거나 30초 이상 정차하고 6상자 이상을 실으면 출발한다. 하역은 초당 0.8상자, 지원 시 1.4상자다. 상점이 가득 차면 판매로 자리가 생길 때까지 기다린다.
- 매 0.1초 생산·소비·상하차를 계산한다. 물건이 없어 사지 못한 수요는 누적 기록하되 다음 시간에 다시 주문하지 않는다. 상자는 나누어 계산하는 교육용 물량 단위다.

항상 `공급처 처음 물자 + 새 공급 = 공급처 재고 + 실은 양`, `전체 실은 양 = 상점 배송량 + 차량 적재량`, `상점 처음 재고 + 배송 = 판매 + 재고`, `수요 = 판매 + 못 산 양`을 만족한다. 출처별 배송량도 보존한다. 도착 전 상점 재고를 임의로 올리거나 정책별 효과 점수를 더하지 않는다.

## 정책

| 정책 | 비용 | 바뀌는 것 | 함께 살펴볼 점 |
| --- | ---: | --- | --- |
| 물류 지름길 연결 | 35 | 학교 북쪽 끊긴 구간을 양방향 도로로 연결 | 모든 차량의 경로가 바뀌어 정체가 다른 곳으로 옮겨갈 수 있음 |
| 화물차 추가 투입 | 35 | 2대→3대, 담당 상점을 다시 분담 | 공장 생산량은 그대로, 도로 위 차량 증가 |
| 시장 하역 인력 지원 | 20 | 네 상점의 실제 하역 속도 증가 | 도착 전에는 효과 없음 |
| 외부 공급처 다양화 | 30 | 서쪽 공급처 개방, 외부 차량이 서쪽부터 두 입구를 번갈아 방문 | 공급량은 늘어도 상점까지의 경로·소요 시간이 달라짐 |

네 정책을 모두 선택하면 120으로 예산을 넘는다. 정책이 많다고 결과를 좋게 보정하지 않는다.

## 화면·기록

왼쪽 **상품 재고**는 실제 상점 건물을 녹색(15상자 이상)·노랑(5~15 미만)·주황(5 미만)·빨강(0.05 미만, 표시상 품절)으로 칠한다. 고정 척도이며 차량에 실린 물자는 상점 재고에 포함하지 않는다. 공급처의 숫자는 배송 전 준비된 물자다. 다시 누르면 일반 도시 색을 복원한다.

**물류 현황**에서 화물차 상태를 보고 눌러 적재량·출처·목적지·담당 상점과 현재 경로를 확인한다. 상점과 공급처 목록은 필요할 때 펼친다. 주민 의견 5개는 네 상점과 공장에 대응한다. 지역 정책은 실제 도로·네 상점·서쪽 입구를 표시하고, 추가 차량 운영은 상단 동네 전체에 표시한다.

결과는 배송량, 못 산 양, 남은 재고, 품절 경험 상점 수, 도착한 구간의 평균 이동시간, 일반 차량 도착, 남은 예산을 비교한다. 완료된 이동 구간만의 평균은 미완료 구간 수와 함께 읽는다. 재고가 많다는 것만으로 좋은 결과라고 표시하지 않는다. 상점별 못 산 양과 공장/이웃 마을별 배송은 접힌 상세에서 볼 수 있다.

v4 기록에 `logisticsModelVersion: goods-delivery-v1`, `logisticsBefore/After`, `cargoTrucks`, `goodsEvents`를 저장한다. 읽기는 네 상점·공급처 ID·수량 보존·시간 일치를 검증하고 현재 도시를 변경하지 않는다. 기존 v3 교통 기록도 유지한다. A4 기록지에는 전후 지표·상점별 부족·주민 의견·학생 생각을 담는다.

## 재현과 한계

`npm run verify:logistics`는 3시드×7정책 조건, 각 600초의 21관측에서 물자·차량 수량을 검증하고 `output/logistics-experiments.json`에 저장한다. 예를 들어 두 번째 아침의 기본 배송 66.9상자·못 산 양 112.3상자는 추가 차량에서 147.5·72.0으로 바뀐다. 첫 번째 아침의 외부 공급처 다양화는 기본 64.9·116.0에서 35.9·144.9로 나빠진다. 이는 실제 운행 결과이며 고정 효과 수치가 아니다.

`simulation/economy/`는 상점·공급처·화물 임무만 관리하고 기존 `dispatchService`를 재사용한다. 교통 엔진과 `Vehicle`/`Trip`을 바꾸지 않았다. `metrics/logistics.ts`, `renderer/logistics.ts`, `ui/logistics.ts`로 비교·표현을 분리했다.

도시 밖의 생산과 입구까지의 운송은 공급률로 단순화했다. 도시 안 경로만 실제로 주행한다. 상품 종류·가격·이윤·경제 성장 점수·재주문·창고 용량·실시간 재경로 탐색은 모형에 없다. 지도 전체 건물 중 지정된 네 상점을 대상으로 하며, 외부 입구와 상점 정차 지점 사이의 마지막 손수레 운반은 애니메이션하지 않는다. 교사·학생 수업과 실제 학교 PC의 검증은 후속이다.
