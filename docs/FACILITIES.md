# 사회과 확장 — Phase 2 공공시설과 주민 참여

현재는 `facility-access-v2`다. 6개 공터·12개 주거 블록, 도서관 55/400㎡·공원 35/900㎡, 서로 다른 공터의 복수 시설 계획으로 확장했다. 아래 v1 수치와 단일 부지 규칙은 이전 단계 기록이다. 현재 규칙은 [지도 확장](EXPANSION.md)을 참고한다.

2026-10-14. `facility-access-v1`은 세 번째 시나리오 **02 우리 동네에 필요한 시설은?**을 제공한다. 동네 소식 → 다른 도시 문제 살펴보기에서 선택한다. 기존 교통·수거 시나리오와 한 번에 하나씩 여는 정보창을 유지한다.

## 학생의 활동

1. 시설 지도에서 도서관/공원을 고르고 접근성 지도를 켠다. 동네별 예상 시간과 이용 가능한 인원을 살핀다.
2. 동네를 선택하면 계산에 사용한 보행 경로와 거리를 본다. 주민 의견은 관찰 사실과 바라는 점을 구분한다.
3. 예산 100 안에서 시설 정책을 고른다. 신설 시설은 북쪽·서쪽·남쪽 주택가 마당 중 한 곳에 짓는다. 부지 미리보기에서 도시의 위치를 확인한다.
4. 정책을 시행하면 같은 주민 수요로 계획 1회를 비교한다. 지역별 수혜와 주민 의견 변화는 접힌 상세에서 확인한다.
5. 선택 이유와 성찰을 적고 JSON 저장·다시 열기 또는 A4 관찰지를 사용한다.

## 계산 규칙

가상 주민은 기존 도시의 7개 주거지, 총 680명이다. 한 주민은 하루의 주된 이용 시설을 도서관 또는 공원 하나로 정한다. 도서관 수요 비율은 시드별·동네별 35~65%이고 나머지는 공원 수요다. 전후 비교에서 인구와 수요는 바뀌지 않는다. 같은 사람이 두 시설의 수혜 인원으로 중복 집계되지 않는다.

`simulation/facilities/walking.ts`의 보행망은 기존 도로가 있는 구간의 양쪽 보도와 교차로 횡단 연결을 사용한다. 동서 도로가 없는 구간에 보행 지름길을 만들지 않는다. 동네 대표점은 블록 중앙이며 기존 건물 사이 통로를 통해 북쪽 보도와 연결한다. 차량 일방통행과 무관하게 보도는 양방향이다.

- 예상 시간 = 경로 거리 ÷ **1.2m/s** + 횡단 횟수 × **15초**.
- 같은 종류 시설까지 Dijkstra 최단 시간 경로를 구한다. **5분 이내**인 시설을 이용 후보로 둔다.
- 모든 후보를 예상 시간이 짧은 순서로 배정하고, 동률은 동네 ID → 시설 ID 순서로 처리한다. 동네의 남은 수요와 시설의 남은 정원을 초과하지 않는다.
- 가까운 시설의 정원이 차면 5분 이내의 다른 같은 종류 시설을 검토한다. 배정이 끝나면 이용 가능·거리 초과·정원 부족의 합은 전체 인구와 같다.
- 이는 명시된 가상 배정 규칙이다. 전체 수혜 인원을 최대화하는 최적화나 민주적 투표 결과, 실제 선착순 예약을 재현하지 않는다.
- 평균 시간은 주민마다 필요한 종류의 **가장 가까운 시설까지**의 예상 시간이다. 실제 배정된 시설까지의 평균 이동시간이나 실제 도착 기록이 아니다.

기본 시설은 남쪽 작은도서관 80명분, 북쪽 공원 90명분, 동쪽 공원 100명분이다. 정원은 하루 이용 가능한 가상 인원으로, 동시 수용 인원이 아니다.

| 정책 | 비용 | 실제 계산과 화면의 변화 |
| --- | ---: | --- |
| 작은도서관 신설 | 60 | 선택한 부지에 도서관과 보행 연결, 하루 140명분 추가 |
| 마당 공원 조성 | 50 | 선택한 부지에 공원과 보행 연결, 하루 160명분 추가 |
| 기존 도서관 확장 | 35 | 남쪽 도서관 정원 80 → 180, 건물 확장. 경로 유지 |
| 서쪽 출입로 개방 | 20 | 남쪽 도서관의 서쪽 진입 연결 추가. 정원 유지 |

한 부지에 한 시설을 신설한다. 도서관과 공원을 함께 신설하면 비용 110이므로 예산상 불가능하다. 단순 효과 점수를 더하지 않고 시설 위치·보행 간선·정원을 바꾼 뒤 재계산한다. 지역별 수혜는 같거나 줄어들 수도 있다. 지역 주민의 말은 각 지역의 수요·시간·배정 결과에서 작성하며 단일 만족도 점수로 합치지 않는다.

## 모듈과 기록

| 모듈 | 역할 |
| --- | --- |
| `simulation/facilities/index.ts` | 부지, 정책, 시설, 독립된 주민 수요와 정원 배정 |
| `simulation/facilities/walking.ts` | 보행 그래프와 거리·시간·경로 |
| `metrics/facilities.ts` | 동일 주민 조건 검사와 전후·지역 비교 |
| `renderer/facilities.ts` | 부지·시설 geometry, 접근성 라벨, 선택 경로 |
| `ui/facilities.ts` | 부지 선택, 접근성 조사, 지역별 결과 |
| `simulation/residents/index.ts` | 사실·의견과 시행 후 변화 |

공통 `scenarios/`, 정책 검증, 카메라·선택, 주민 의견창, 기록·인쇄를 재사용한다. `FacilitySimulation`은 공통 도시 렌더링을 위해 교통 엔진의 빈 상태를 이용하지만 차량·보행 수요를 넣거나 시간을 진행하지 않는다. 등록된 `clock: planning`은 일시정지·배속·관찰 시간 선택을 숨긴다.

기록 형식은 additive 확장한 **schemaVersion 4**다. `scenarioId: facilities`, `facilityModelVersion: facility-access-v1`, `timeUnit: planning-round`, `round: 1`, `duration: 0`, `facilityPlan`, `facilitiesBefore/After`를 저장한다. 기존 차량/보행 수요는 빈 배열, 시간은 0이며 계획을 실제 이동 관찰처럼 표기하지 않는다. 읽기 전용 기록은 지역 표·부지·근거·성찰을 복원하고 현재 실험을 바꾸지 않는다. v3 교통과 v4 수거 기록 호환을 유지한다.

## 범위와 한계

전체 주민이 화면에서 실제로 걸어가는 시뮬레이션은 아니다. 시설 계획 화면의 **계산된 예상 접근성**과 교통·수거 화면의 기존 60명 보행 애니메이션을 분리한다. 공사 기간·유지비·예약 시간대·대기 줄·이동 약자의 속도·실제 신호 대기는 모델링하지 않는다.

마당의 시설과 동네 대표점이 같으면 해당 동네의 계산 거리는 0이다. 각 집의 문부터 거리를 재는 모델이 아니며, 지도상의 건물 크기와 가상 이용 정원을 실제 건축 면적으로 해석하지 않는다. 부지와 시설 형태는 고정이고 자유 배치·철거는 없다. 현재 전체 보행망은 연결되어 있으며 보행 그래프 자체는 경로가 없는 경우도 처리한다.

Phase 3 환경·개발은 [별도 시나리오](ENVIRONMENT.md)로 추가했다. 물류·지역 홍보, 교사 설정과 실제 학교 PC·수업 검증은 후속 범위다. 검증 증거는 [VERIFICATION](VERIFICATION.md), 성능 조건은 [PERFORMANCE](PERFORMANCE.md)에 기록한다.
