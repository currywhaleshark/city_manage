현재는 확장 지도용 `development-environment-v2`다. 산업지구 공장·처리시설과 17개 관찰 지점을 사용한다. 새봄천은 지형이며 수질·하류 오염 이동은 아직 계산하지 않는다. 아래 v1 수치는 이전 지도 기록이며 [지도 확장](EXPANSION.md)에 변경 사항을 정리했다.

## 활동 흐름

환경 자료에서 지정 부지·녹지·시설과 동네별 부담을 살펴보고 주민 의견을 듣는다. 예산 100 안에서 개발·보전 정책을 선택하면 도시와 수요를 다시 구성하고 3·7·10분을 관찰한다. 추가 차량은 기존 자동차와 함께 움직이며 도로·신호·보행 횡단·앞차 대기·교차로 예약의 영향을 받는다. 결과는 늘어난 공간, 줄어든 녹지, 기존 차량과 추가 차량의 도착, 장소별 부담을 따로 비교한다. 선택 이유·성찰·주민 의견을 저장하고 기록 열기와 A4 인쇄를 지원한다.

기본 화면에서는 도시를 유지하고 환경 자료의 지역·교통·부지·계산 방법을 접어 둔다. 환경 레이어는 **현재** 부담을 숫자와 낮음/중간/높음 색으로 표시한다. 결과와 지역 표는 **관찰 중 평균**을 사용한다. 자료·주민 의견·정책·선택 정보창은 하나씩 열린다.

## 부지와 정책

기존 도시의 도로·16개 블록을 유지한다. 남동쪽 산업 확장 부지 `(72, 108)`와 남서쪽 주거 확장 부지 `(-72, 108)`를 각각 24×12 = 288㎡로 둔다. 기존 공장 서쪽의 완충 띠는 x=56~60, z=52~88 및 z=104~114로, 도로를 비워 둔 184㎡다. **관리 대상 면적 760㎡**만 집계하며 도시 전체 녹지 면적이라고 표현하지 않는다.

| 정책 | 비용 | 적용 내용 |
| --- | ---: | --- |
| 산업시설 확장 | 40 | 192㎡ 개발, 새 일터 이용 자리 48명분, 출근 차량 48건 |
| 주거지 확장 | 30 | 192㎡ 개발, 새 거주 공간 48명분, 등교·출근 차량 24건 |
| 녹지 보전 | 15 | 두 부지에 각 192㎡ 보전 지정, 개발을 각 96㎡ 이하로 제한 |
| 완충 녹지 조성 | 20 | 기존 184㎡ 녹지 띠에 나무 식재, 띠를 가로지르는 산업시설 부담 감소 |
| 개발 규모 축소 | 10 | 선택한 개발을 각 96㎡로 축소, 새 공간과 차량 수요도 절반 |

남은 녹지 = 760 − 개발 면적이다. 완충 식재는 기존 녹지를 이용하므로 녹지 면적에 중복해서 더하지 않는다. 보전 정책을 단독으로 시행하면 현재 면적·교통은 그대로이고 보전 지정 면적만 바뀐다. 기존 일터를 없애거나 경제 점수를 깎지 않는다. 보전과 규모 축소를 함께 선택해도 96㎡보다 더 줄이지 않는다. 개발이 없으면 규모 축소의 물리적 변화도 없다. 이 조건은 정책 설명에 표시한다.

수용 규모는 교육용 가상 인원이며 실제 고용·입주·경제 성장률이 아니다. 개발 면적과 건물 바닥 범위는 연결하지만 건축 기준에 따른 수용 인원을 산정하지 않는다. 공사 기간·세수·운영비·집값·공실은 제외한다.

## 추가 차량과 공정한 비교

같은 시드의 기존 자동차 140대와 보행자 60명은 전후에 정확히 같다. 개발 종류마다 별도 시드 스트림으로 차량을 생성한다. 산업시설은 ID 2000~2047, 주거지는 3000~3023을 쓰며 기본 수요 ID와 겹치지 않는다. 산업 차량은 서쪽에서 남동쪽 연결 도로 지점으로 출근한다. 주거 차량은 남서쪽 연결 지점에서 학교·업무 지역으로 간다. 축소 정책은 기존 생성 목록의 앞 절반을 유지하므로 남은 차량의 ID·출발 예정 시간·경로 조건은 바뀌지 않는다.

추가 수요는 비용에 붙인 보너스가 아닌 실제 `Trip`이다. 기본 차량 엔진을 그대로 사용하며 별도 순간이동·도착 보정은 없다. 산업시설 이용 변화는 **실제 출근 차량 도착 / 산업 출근 수요**로도 표시한다. 연결 도로 지점 도착을 집계하고 진입로·주차 애니메이션은 생략한다. 차량 한 대를 실제 근로자 한 명이나 주거 주민 한 명으로 해석하지 않는다.

전후 전체 수요가 다르므로 기존 `compareExperiments`에 넘기지 않는다. `compareEnvironment`는 시드·관찰 시간·기존 차량 140건·보행 수요의 완전 일치를 확인한다. 결과에는 **같은 기존 차량의 도착 수**와 **개발로 추가된 수요·도착**을 분리한다. 전체 도착 수 증가만으로 교통이 좋아졌다고 결론내리지 않는다.

## 가상 환경 부담

이 모델은 정책 비교를 위한 가상 규칙이며 **실제 소음, 오염 농도, 건강 위험, 법적 기준, 환경영향평가**를 산출하지 않는다. 외부 실측 자료나 전문 환경 모델을 사용하지 않았다.

거리 가중치는 `1 / (1 + 거리 / 기준거리)²`다.

- 시설 성분: 기존 공장 강도 40 + 확장 산업시설 강도 `30 × 개발 면적 / 192`. 기준거리 45m를 적용한다.
- 완충 효과: 산업 발생점과 관찰 장소 사이 직선이 완충 띠의 중앙선을 해당 z 범위 안에서 가로지르면 해당 시설 성분에 0.65를 곱한다. 도로가 있는 틈을 가로지르면 적용하지 않는다. 바람·확산·반사·지형을 재현하지 않는다.
- 교통 성분: **실제 도로 위 차량** 각각에 가중치 0.8과 기준거리 38m를 적용해 합한다. 출발지 대기·아직 출발하지 않은 수요는 도로 위 차량으로 세지 않는다. 차량 종류별 배출량이나 속도별 소음 모델은 없다. 완충 정책은 교통 성분을 직접 줄이지 않는다.
- 현재 부담 = 시설 성분 + 교통 성분. 매 1초의 고정 시뮬레이션 시각에서 표본을 모으며 결과는 그 산술평균이다. 첫 1초 전에는 평균을 ‘집계 중’으로 표시한다.
- 낮음 <10, 중간 10~20 미만, 높음 ≥20은 가상 지도 범례다.
- 관찰 장소는 주거지 7곳 + 학교 + 기존 공장 + 새 주거 부지, 총 10곳이다. 새 부지도 전후 모두 같은 위치를 비교한다. 전체 평균은 장소별 동일 가중치이며 인구 가중 평균이 아니다.

개발·주거 정책에 주민 만족도나 경제 점수를 직접 더하지 않는다. 주민 4집단의 의견은 평균 부담·이용 공간·녹지·기존 교통의 관찰 사실과 각자의 요구를 구분해 표시한다. 완충으로 달라지지 않는 장소도 남는다.

## 모듈과 기록

| 모듈 | 역할 |
| --- | --- |
| `simulation/environment/index.ts` | 부지·정책·추가 수요·실제 주행 상태의 1초 표본·부담 집계 |
| `metrics/environment.ts` | 기존 조건 동일성 검사와 개발·지역 비교 |
| `renderer/environment.ts` | 개발 면적에 맞는 건물·잔여 녹지·완충 식재·환경 라벨 |
| `ui/environment.ts` | 환경 관찰·부지 선택·지역 결과 |
| 기존 시나리오·주민·기록 모듈 | 문제 선택·의견·저장/열기·인쇄 공유 |

차량 엔진·기존 교통 정책·보행 신호 계산은 변경하지 않았다. `EnvironmentSimulation`은 기존 엔진 실행 뒤 1초마다 관측만 한다. 모델 테스트에서는 같은 전체 수요를 일반 `TrafficSimulation`에 넣은 결과와 매 관찰 시각의 모든 차량 위치, 최종 통계가 정확히 같다.

기록은 기존 **schemaVersion 4**를 확장한다. `environmentModelVersion`, `environmentBefore/After`, `backgroundDemand`, `addedDemandBefore/After`, `demandBefore`와 공통 결과·정책·주민 의견·근거·성찰을 저장한다. `demand`는 시행 후 전체 수요다. `timeUnit: seconds`와 관찰 시간을 유지하며, 기존 수요가 완전히 같아야 하는 교통 전용 `analysis`는 넣지 않는다. 읽기는 시간·면적 보존·관찰 지점·수요/도착·정책 예산을 검사하며 현재 실험을 바꾸지 않는다.

## 남은 범위

자유 부지 배치, 실제 환경 보정, 날씨·오염 물질·건강 영향, 고용·입주 수요 반응과 경제 순환은 제외한다. 기존 보행자 60명은 같은 수요로 유지하며 개발에 따른 추가 보행 인구는 생성하지 않는다. 다음 단계는 **Phase 4 물류·지역 간 교류**, 이후 Phase 5 지역 홍보다. 학교 PC·교사·학생 수업 검증도 별도로 남아 있다.

재현: `npm test`, `npm run test:browser`, `npm run verify:environment`, `npm run verify:performance`, `npm run build`, `npm run verify:production`. 증거는 [VERIFICATION](VERIFICATION.md)과 [PERFORMANCE](PERFORMANCE.md)를 참고한다.
